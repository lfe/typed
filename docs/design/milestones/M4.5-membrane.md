# Milestone M4.5 — The Membrane (Deep Validators & `decode`)

> **Goal:** the deep, recursive half of runtime enforcement — generated **validators**
> that check a term against a type all the way down, and a **`decode`** entry that turns
> untrusted external input into a typed value *gracefully*. This is the home of the
> project's motivating example: **"typed user input → type error."**
> **Builds on:** M4 (closed) — always-on head guards + the structured type-error.
> **Design:** [[typed-runtime-enforcement]] (memory) — the full model.
> **Ledger:** [M4.5-membrane-ledger.md](M4.5-membrane-ledger.md). **CC prompt:**
> [M4.5-cc-prompt.md](M4.5-cc-prompt.md). **Iteration budget:** 5.

## Why this is its own milestone

M4 gave every typed function head a **shallow** guard (right shape, right tag/arity) that
**crashes** on violation — perfect for *internal* contracts (let-it-crash). But untrusted
*external* input (HTTP/JSON/form data, ETS reads, `binary_to_term`) needs two things M4
didn't do:

1. **Deep** checking — validate an ADT's *fields* and *nested* values recursively, not
   just the top constructor.
2. **Graceful** failure — return `#(error type_error)` you can turn into a 400, not crash.

That's the membrane. The guard and the validator are the two faces of the same type
information: **guards crash (internal), validators return (external).**

## In scope

- **Deep validators:** `(validate <type> term) -> #(ok term) | #(error type_error)`,
  generated per declared type, **recursive** over constructor fields and nested ADTs;
  base-type validators built in. On failure the error carries a **`path`** to the failing
  field (e.g. `[shipped, tracking]`) so it's teaching-grade.
- **`decode` membrane entry:** `(decode <type> untyped) -> #(ok T) | #(error type_error)`
  — the public `dynamic → T` boundary; runs the validator; **never crashes**.
- **Web-input demo (headline):** a fixture that decodes an untyped term resembling parsed
  input (a map/tuple) into an ADT — valid → `#(ok …)`; invalid (wrong field type / wrong
  tag / missing field) → `#(error type_error)` with a teaching message (the 400 case).
- **Guards-vs-validators duality:** the *same* bad value **crashes** when passed to a
  typed function head (M4 guard) but **returns** `#(error …)` through `decode`. Test both
  on one value; document the distinction.
- **Human render helper** (the M4-4 caveat): render the structured type-error Gleam-style
  (expected / got / path), exact-snapshot tested — the runtime analog of the compile-time
  diagnostic engine.
- **Standardize the error term on a MAP** `#{expected, got, path, …}` (the M4 note): move
  the M4 guard fallback and its tests to the same map shape so guards and validators share
  one error type the render helper consumes.
- **Validator cross-backend matrix:** validators correct across tagged-tuple/enum/
  transparent (native-record runtime deferred, OTP 29+); **exact** assertions.
- **Full M0–M4 regression** green; standing discipline.

## Out of scope (later)

- **Native-record runtime** validators (OTP 29+, rides M1-8).
- **Coercion** during decode (e.g. binary→integer); decode validates, it does not convert.
- **Higher-order / contract blame** across funs; **message/process** boundary enforcement
  (session types — research, never v0).
- **Framework/HTTP integration helpers** (a JSON-map→ADT convenience layer can be a later
  milestone); **redundant-guard elision** (perf).

## Definition of done

Every ledger row final with SHA-anchored, CI-green evidence. `decode` turns untyped input
into `#(ok T)` or a graceful, teaching-grade `#(error type_error)` with a path; the
web-input demo works both ways; guards-crash-vs-validators-return is tested on one value;
the structured error is a map rendered by the helper (exact snapshot); validators are
matrix-correct across the testable backends; full M0–M4 regression green.

## Standing discipline (in force)

[[typed-test-discipline]]: exact `assert_eq!`/snapshots (never `.contains()`); test every
backend; unwired/cfg-test ≠ `done`; test the criterion's actual subject.
[[cc-editing-safety]]: no blind `sed`; `git checkout` to recover; `make check` after bulk edits.
