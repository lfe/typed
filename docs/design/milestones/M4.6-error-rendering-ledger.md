## CDC Verification

**Verifier:** Claude (CDC), 2026-06-07, against `58bc338` / `b172690`. **Method:** static
inspection of `validators.rs` (`generate_render_helper`), `eetf.rs`, and the migration.

**E-1/E-2/E-5 — genuinely done, verified.** Both guards (`(map 'expected … 'path ())`) and
validators (`(map 'expected … 'path P)`) emit the **map**; all 40 CT migrated from
`proplists:get_value` → `maps:get`; full M0–M4.5 regression green; `make check` clean. The
load-bearing change is real and clean. ✅

**E-3/E-4 — the deferral is MISDIAGNOSED; reopened.** CC's stated blocker — "the EETF
encoder doesn't support `(call 'mod 'fun …)`" — is **incorrect** on two counts:
1. **The encoder already supports it.** `(call (quote maps) (quote get) …)` is just a list
   of symbols + `(quote …)` sub-lists; `eetf.rs encode_sexp` handles `Symbol→atom` and
   `List` generically. Nothing is missing. The *actual* failure was that
   `generate_render_helper` emits the **surface** form `(maps:get 'expected info)` (colon
   head), which works in LFE *source* (reader desugars it) but NOT when forms go straight to
   `lfe_codegen` via EETF (no reader). The canonical internal form is `(call 'maps 'get …)`.
   So it's the wrong *form*, not a missing *capability*.
2. **The render helper shouldn't be generated at all.** It's a fixed, **type-agnostic**
   function (`type_error` map → string). Generating it per-type in `validators.rs` is what
   pulled in the remote-call-emission problem. It belongs as **hand-written runtime support**
   (a function in `typed_driver.erl` or a new `typed_rt` module), compiled normally, where
   `maps:get`/`io_lib:format` are trivial and no codegen/EETF is involved.

→ E-3/E-4 are NOT blocked; they're a small, straightforward task via the right approach
(hand-written `render-type-error/1` runtime support). Remove the dead `generate_render_helper`
from `validators.rs`.

**Disposition:** the map standardization (the load-bearing half) is done and clean. The
render helper was deferred on a false premise — reopened, to be done as hand-written runtime
support (not generated). Small close-out.
