# Milestone M9.1 — Expander Phase 0: Oracle + Golden Corpus + Harness

> **Goal:** build the faithfulness infrastructure for the Tier-1 expander port — an
> **Erlang oracle** that expands LFE forms using the real `lfe_macro`, a **golden corpus**
> covering Tier-1 categories, and a **diff harness** — and pin the conventions (`keep`,
> printer, gensym) the Rust port (M9.2/M9.3) must match. **No Rust port in this milestone.**
> **Builds on:** M0–M9 (closed). **Design:** [05-lfe-expander-port.md](../05-lfe-expander-port.md)
> (Phase 0). **Iteration budget:** 5.

## Why (and why first)

The typed driver runs `lfe_lint` + `lfe_codegen` + `compile:forms` — **no `lfe_macro`**.
So no macro expansion happens on passed-through forms; backquote was only the first
symptom (M9 D-4), and `cond`/`let*`/`do`/`defrecord`/etc. break identically. We are going
to port LFE's Tier-1 expander to Rust (M9.2/M9.3). Before writing any Rust, we need a
**ruler**: an oracle that produces the *exact* expansion LFE itself would, so the port can
be diffed against ground truth. This milestone builds that ruler and the test corpus. It
is cheap, de-risks the whole series, and produces the regression suite the port will be
graded on.

## The oracle (faithful by construction)

An Erlang escript that wraps the **real `lfe_macro`**, so its output is ground truth:
`lfe_io:read_file/1` → `lfe_env:new/0` → `lfe_macro:expand_form_init/2` →
`lfe_macro:expand_form/4` (fold per form, threading `Env` + `#mac{}`) → `lfe_io:print1/1`.
It reads an `.lfe`/`.lfet` file (and/or stdin) and prints the fully-expanded forms.

## Conventions to PIN (these bind the Rust port)

- **`keep`** — keep vs. drop macro/function definitions in the output. Pick the value
  that matches what the typed pipeline needs (likely `keep=true` so defs survive for
  inspection; document the choice and rationale).
- **`deep`** — `true` (full expansion).
- **Printer** — the diff depends entirely on a stable serialization. Pin `lfe_io:print1/1`
  as the canonical form, OR define a structural-comparison approach (re-read both outputs
  and compare terms) so the Rust port isn't hostage to whitespace. Document which.
- **Gensym fidelity** — record the exact gensym name formats (`|-N-|`, `do$^N`) and
  counter-threading order, since generated names leak into output and the Rust port must
  reproduce them byte-for-byte.

## The golden corpus (covers Tier-1 categories)

A set of small LFE inputs + their oracle-produced golden outputs, committed, covering the
categories the Tier-1 port (M9.2/M9.3) must handle:

- **Backquote/quasiquote:** nested backquote, `comma`, `comma-at` splicing into **lists,
  tuples, and maps**; the `` `#(unix ,x) `` tuple-pattern idiom; cons/append optimizer
  cases.
- **Core-form recursion:** macros nested inside `case`/`let`/`lambda`/`progn`/`if`/`try`/
  comprehensions (so M9.2 proves it recurses everywhere).
- **Static predef macros:** `c*r` (caar…cddddr), comparison aliases (`!=`/`===`/`!==`),
  `list*`, `let*`, `flet*`, `do`, `fun`, `?`, `MODULE`, `LINE`, colon-call sugar.
- **CL `def*` lowering:** `defun`, `defmacro`, `flet`, `fletrec`, `macrolet`, `deftype`,
  `defspec` → their `define-*` core forms.
- **defrecord / defstruct:** generating the accessor-macro families.

(Tier-2 eval-time macros and Tier-3 includes/QLC are OUT — the corpus stays within Tier 1.)

## In scope

- The oracle escript (committed, runnable; uses the project's LFE 2.2.1 ebin).
- The golden corpus: inputs + oracle-generated golden outputs, committed.
- A harness/make-target to (re)generate and verify golden outputs (and a documented plan
  for how M9.2+ will diff Rust output against these goldens).
- A short `docs/` note pinning the `keep`/`deep`/printer/gensym conventions + rationale.
- `make check` clean; existing M0–M9 suites unaffected.

## Out of scope

- Any Rust expander code (that's M9.2/M9.3).
- Tier-2 (eval-time user macros, eval-when-compile) and Tier-3 (`.hrl`/QLC/imported
  macros) corpus entries — the oracle *can* expand them, but they're not part of the
  Tier-1 port we're grading.

## Definition of done

The oracle expands LFE files via the real `lfe_macro` and prints fully-expanded forms; a
committed golden corpus covers all Tier-1 categories with oracle-produced goldens; a
harness regenerates/verifies them; the `keep`/`deep`/printer/gensym conventions are pinned
and documented; `make check` clean.
