> **Design refs:** [design v0](../01-design-v0.md) §6, §8; [M3 ledger](M3-contracts-ledger.md)

## The four deferrals to finish

1. **Engine routing for M3 errors.** M3's type errors carry teaching-grade *messages*
   but are emitted via ad-hoc `eprintln!`, not through the M2 `DiagnosticCollector` — so
   they lack the span+caret rendering (and JSON) that exhaustiveness errors get. Route
   them through the engine so *all* diagnostics render uniformly (human + JSON).
2. **`case/typed` branch-body typing (M3-6).** Today `case/typed` synthesizes `Dynamic`.
   Make each clause body **checked against the expected result type**; synthesize the
   match's result type; reject a branch of the wrong type. Integrates with M2
   exhaustiveness (which already guarantees the cases are complete) and with M3's
   body-vs-`:returns` (a `case/typed` that *is* a function body checks against `:returns`).
3. **README `describe` demo (M3-11).** The public README shows `order-status` + `describe`
   as the project's face. Make it real: the correct constructor version **type-checks
   clean**; the wrong (string-pattern) version is **rejected**. This is the integration
   test that proves items 1+2 together.
4. **Basic polymorphic contracts (M3-14).** Type variables in `:args`/`:returns` checked
   **consistently**: `(:args ((x a) (y a))) (:returns a)` requires both args the same
   type and returns that type; identity accepted; inconsistent use rejected. A small,
   single-level unifier — **not** full Hindley-Milner.

## In scope

- Items 1–4 above.
- **Standing test discipline** ([[typed-test-discipline]]): every new diagnostic test
  asserts the **exact** rendered output (`assert_eq!`/golden snapshot), never
  `.contains()`; every backend/representation claim is tested, not assumed; absent
  capability is `deferred`, not `done`.
- **Full M0–M3 regression** stays green; line injection preserved.

## Out of scope (later)

- **Full Hindley-Milner / global inference / let-polymorphism**, nested/higher-rank
  generic instantiation (M3.5 does single-level type-var consistency only).
- **Nested/Maranget exhaustiveness**, the full BIF prelude, bit-syntax/comprehension/HOF/
  guard typing.
- **Runtime enforcement** (guards + validators) — M4 ([[typed-runtime-enforcement]]).
- **Native-record runtime** (OTP 29+, rides M1-8's deferral).

## Definition of done

Every ledger row final with SHA-anchored, CI-green evidence. All checker diagnostics
render through the engine (span+caret, human + JSON); `case/typed` branch typing rejects
a wrong-typed branch with an exact-snapshot diagnostic; the README `describe` example
type-checks (correct) and is rejected (strings); basic polymorphic contracts check
consistently. Full M0–M3 regression green.

## Size note

This is a consolidation milestone and should close in 1–2 iterations. The one item with
real type-theory weight is **#4 (polymorphic unification)** — if it threatens the budget,
split it out (M3.6) rather than grind; items 1–3 are the load-bearing cleanup.
