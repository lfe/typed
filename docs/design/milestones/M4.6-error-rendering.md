# Milestone M4.6 — Error Term Standardization & Render Helper

> **Goal:** finish the two display-polish items deferred from M4/M4.5 — standardize the
> runtime type-error on a **map** shared by guards and validators, and add a **human
> render helper** so runtime type errors read as teaching-grade as the compile-time ones.
> **Builds on:** M4 (guards, closed) + M4.5 (validators/decode, closed).
> **Ledger:** [M4.6-error-rendering-ledger.md](M4.6-error-rendering-ledger.md).
> **CC prompt:** [M4.6-cc-prompt.md](M4.6-cc-prompt.md). **Iteration budget:** 5 (≤2 expected).

## The two items

1. **One error shape — a map.** Today the structured type-error is a **proplist**
   (`[{expected,…},{got,…},{path,…},…]`), raised by the M4 guard fallback and returned by
   M4.5 validators/`decode`. Standardize on a **map** `#{expected => T, got => V, path =>
   P, …}` (optional `function`/`arg` for the guard-crash case), shared by *both* paths, so
   there is exactly one runtime type-error type. Migrate the existing code and all tests.
2. **A human render helper.** `(render-type-error TE) -> string` that prints the error
   Gleam-style — expected vs got, the path to the failing field — the runtime analog of
   the compile-time diagnostic engine. Works for both a guard-crash error and a
   validator/`decode` error (same shape → same render).

## In scope

- Migrate the runtime type-error term from proplist → **map** `#{expected, got, path,
  function?, arg?}`, in both the M4 guard fallback and the M4.5 validators/`decode`.
- Update every existing test that pattern-matches the error term to the map shape; keep
  them green (full M0–M4.5 regression).
- **Render helper** `render-type-error/1` → a teaching-grade string (expected / got /
  path); **exact-snapshot** tested.
- Render helper verified on **both** a guard-crash error and a validator-return error.

## Out of scope (later)

- A JSON variant of the *runtime* error render (the compile-time diagnostics already have
  JSON; a runtime-JSON helper can be a later add if a use case appears).
- Native-record runtime (OTP 29+); coercion; framework/HTTP helpers.

## Definition of done

The runtime type-error is a single map shape used by guards and validators; the render
helper turns it into a teaching-grade string, exact-snapshot tested, for both the crash and
return paths; full M0–M4.5 regression green.
