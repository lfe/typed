# Milestone M9.3 — Expander Phase 1b: Predef Macros + Records (+ the validation gate)

> **Goal:** complete the Tier-1 expander port — the static `exp_predef` table,
> `defrecord`/`defstruct` generation, and gensym byte-fidelity — and **stand up the
> Rust↔golden harness so EVERY oracle golden goes green from the Rust side**, retroactively
> validating M9.2's backquote port. Plus the two carries from M9.2. **Builds on:** M9.1
> (oracle/corpus/conventions), M9.2 (backquote + recursion + run-over-all-forms).
> **Design:** [05-lfe-expander-port.md](../05-lfe-expander-port.md) (Tier 1) +
> [06-expander-conventions.md](../06-expander-conventions.md) (contract). **Budget:** 5.

## Why this is the gate

M9.2 ported backquote but could not validate it against the oracle, because the goldens are
**full-file** expansions whose top level needs predef lowering (`defmodule`→`define-module`,
`defun`→`define-function`). M9.3 adds that predef table — which finally lets the **Rust↔golden
harness** run on every corpus file. So M9.3 isn't just "more macros": it's where the whole
M9.1–M9.3 arc proves itself by matching ground truth. After M9.3 the typed pipeline can compile
real LFE that uses Tier-1 macros (`cond`/`let*`/`do`/`defrecord`/…), and we'll *know* it matches
LFE because the oracle says so.

## In scope

- **Static `exp_predef` table (pure rewrites):**
  - `c*r` accessors (`caar`…`cddddr`);
  - comparison aliases (`!=`→`/=`, `===`→`=:=`, `!==`→`=/=`);
  - control/binding sugar: `list*`, `let*` (→ nested `let`), `flet*`, `do` (→ letrec-function
    loop), `fun/2,3` (→ gensym arg lists), `?` (receive-timeout);
  - `MODULE`/`LINE`; colon-call sugar (`(mod:fun …)` and `m:f` → `(call 'mod 'fun …)`).
- **CL `def*` LOWERING (Tier-1 — the definition transform, NOT macro eval):** `defmodule`→
  `define-module`, `defun`→`define-function`, `defmacro`→`define-macro`, `flet`→`let-function`,
  `fletrec`→`letrec-function`, `macrolet`, `deftype`→`define-type`, `defspec`→
  `define-function-spec`. (A user macro's *body being evaluated* remains Tier 2 / out of scope —
  we only reproduce the **lowering** so output matches the golden.)
- **`defrecord`/`defstruct` generation** — the full accessor-macro family (`make-`, `is-`,
  `match-`, `set-`, field getters/setters), matching `defrecord.expanded`.
- **Gensym byte-fidelity** — `|-N-|` (vc) and `do$^N` (fc) with the exact counter-threading
  order, so generated names match the oracle byte-for-byte (`do`/`fun` depend on this).
- **THE VALIDATION GATE (carried B-4):** stand up the Rust↔golden harness (Rust expander →
  EETF → Erlang re-read → `prettyprint1` → compare golden) and turn **ALL** committed goldens
  green from the Rust side: `backquote.expanded` (retroactively validating M9.2),
  `core-forms.expanded`, `predef-macros.expanded`, `defrecord.expanded`. Wire into CI.
- **Carried B-3:** a **fully-plain `(defun …)`** (NOT `defun/typed`) with a `case` containing
  `` `#(unix ,x) `` that compiles + runs + binds the var — the actual plain-form subject (fix
  end-to-end if the test exposes a real gap).
- **Full M0–M9.2 regression**; standing discipline.

## Out of scope (future, delegated)

- Tier 2 — eval-time user macros, `eval-when-compile`/`set`, `let-function`/`letrec-function`
  bodies *called* at expand time (the lowering is in scope; the *eval* is not).
- Tier 3 — `.hrl` includes (epp/erl_parse), QLC, imported macros (`code:load_file`).
- These stay behind the documented "delegate to the oracle/BEAM" boundary.

## Definition of done

The static predef table + def* lowering + defrecord/defstruct generation are ported with gensym
byte-fidelity; **the Rust↔golden harness turns ALL oracle goldens green from the Rust side**
(backquote retroactively + core-forms + predef + defrecord); the fully-plain-`defun` backquote
case compiles+runs (carried B-3); full M0–M9.2 regression green; positions intact; `make check`
clean. After this, Tier-1 expansion is complete and oracle-validated.
